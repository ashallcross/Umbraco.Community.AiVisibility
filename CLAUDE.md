# Project Instructions for Claude Code

Umbraco.Community.AiVisibility — Expose Umbraco published content to LLMs and AI search engines: per-page Markdown rendering, `/llms.txt`, and `/llms-full.txt`, plus AI traffic request log + dashboard, robots.txt audit, content negotiation, and link/header advertisement.

This file captures repo-level conventions any contributor (human or AI) working in this codebase should know about. Adopter-facing reference lives in [`docs/`](docs/); package-internal architecture lives in `Umbraco.Community.AiVisibility/`.

## Rules

- **Tests**: `dotnet test Umbraco.Community.AiVisibility.slnx` — never bare `dotnet test` (multi-project repo; bare call fails with MSB1011).
- **Package management**: this repo uses Central Package Management. All NuGet versions live in the root `Directory.Packages.props`. csproj `<PackageReference>` entries do **not** carry version attributes — add a `<PackageVersion>` line to `Directory.Packages.props` first.
- **v13 package is frozen**: `Umbraco.Community.AiVisibility.V13` receives no further development — no fixes, tests, or releases. It stays at its last published 1.2.x version and is unsupported once Umbraco 13 reaches end of support (December 2026). Fix and test the v17 package only. If a change breaks the V13 build, stop and ask the maintainer whether to remove the V13 projects from the solution instead of fixing them.
- **Architectural principle**: the Umbraco template is the canonical visual form of content. The package renders pages through Umbraco's normal pipeline and converts the resulting HTML to Markdown — it does **not** walk properties and reconstruct content. See [`docs/architecture.md`](docs/architecture.md) for the adopter-facing summary.
- **Anti-patterns explicitly NOT shipped**: User-Agent sniffing, `<meta name="llms">`, `/.well-known/ai.txt`, JSON-LD-as-AI-strategy, AI/human toggle UI. See the [README](README.md#what-this-package-does-not-do-and-why)'s "What this package does NOT do" section for the rationale on each.
- **Spec-bound external contracts**: `/llms.txt`, `/llms-full.txt`, `*.md` routes; `Accept: text/markdown` content negotiation; the `Link: <uri>; rel="alternate"; type="text/markdown"` discoverability header (RFC 8288 — the value the package actually emits, see [`DiscoverabilityHeaderMiddleware.cs`](Umbraco.Community.AiVisibility/Routing/DiscoverabilityHeaderMiddleware.cs)); `data-llms-content` and `data-llms-ignore` extraction-region attributes; `<link rel="alternate" type="text/markdown" …>` HTML markup. These contracts are stable across versions; package-internal identifiers were renamed pre-1.0 but the public-facing contracts above were NOT.
- **Umbraco v17 official requirements** (verified against [`docs.umbraco.com/umbraco-cms/fundamentals/setup/requirements`](https://docs.umbraco.com/umbraco-cms/fundamentals/setup/requirements) 2026-04-28): .NET 10.0+, Node.js 24.11.1+, SQL Server 2016+ or SQLite-in-dev. Any Backoffice-bundle rebuild must use Node ≥ 24.11.1 (the local dev floor — there is no CI); do NOT downgrade to Node 20.
- **Umbraco extension/package template** (verified against [`docs.umbraco.com/umbraco-cms/extending/packages/creating-a-package`](https://docs.umbraco.com/umbraco-cms/extending/packages/creating-a-package) 2026-04-28): the `dotnet new` short name is `umbraco-extension` (NOT `umbracopackage`, which appeared in older docs). Install via `dotnet new install Umbraco.Templates`.

## Umbraco Backoffice & Extension Code — Skill-Load Reflex (MANDATORY)

Umbraco HQ maintains official `umbraco-*` Agent Skills (one per backoffice extension type + a testing set, with current v17 Lit/Bellissima patterns and working examples). They install user-level at `~/.claude/skills/` and load **on demand**.

- **Before writing ANY backoffice/extension code, STOP and load the matching `umbraco-*` skill first.** Do **not** write it from memory — that produces stale Umbraco v8 / AngularJS patterns. State which skill(s) you load and why before writing code. If no `umbraco-*` skill matches, say so explicitly rather than guessing.
- **Type → skill examples**: Section → `umbraco-sections`; dashboard → `umbraco-dashboard`; tree → `umbraco-tree`; workspace → `umbraco-workspace`; modal → `umbraco-modals`; entity action → `umbraco-entity-actions`; property editor → `umbraco-property-editor-schema` **+** `umbraco-property-editor-ui`; Management API controller (C#, still version-specific) → `umbraco-controllers`; backoffice tests → `umbraco-testing` (router) then the specific testing skill.
- **Scope**: these skills cover the **v17 backoffice only** (the Bellissima/Lit + Vite + TypeScript client at [`Umbraco.Community.AiVisibility/Client/`](Umbraco.Community.AiVisibility/Client/)). Pure server-side C# has no backoffice skill — "no skill applies" is a valid answer there.
- **Per-developer install (one-time)**: skills are user-level, not vendored into this repo. To install: `claude plugin marketplace add umbraco/Umbraco-CMS-Backoffice-Skills` then install both plugins; or clone that repo and copy `plugins/*/skills/*` into `~/.claude/skills/`. They register at session start.
